# akashiの開発経緯と次回に生かすこと

2026年11月16日の開発記録。次に作業する人が、現在の仕様の理由と、繰り返したくない失敗を判断できるように残す。

公開名は当初のRedSheetから、ユーザーが選んだ **akashi** へ変更した。タグラインは **「赤シートをパソコンでも。」**。名前の検討段階ではZurashiなども候補にしたが、採用したのはakashi。

## 作りたかった体験

学生が紙の赤シートで慣れ親しんだ暗記の手つきを、WindowsのPDFや問題集にも持ち込む。隠す機能に加えて、赤いシートが「今どの問題に取り組んでいるか」の目印になることも重要だった。

紹介映像で伝えたいのも、この馴染みのある道具がWindowsでも使えること。学習方法の説明や機能一覧ではなかった。

## 仕様が変わった理由

| 段階 | 判断と理由 | 対応するコミット |
|---|---|---|
| 新規実装 | 手元のTRPSは実行ファイルのみでソースがなかった。元のアプリを残し、別のWinFormsアプリとして実装した | `f9e093e` |
| 文字色の変換 | 半透明の色を重ねるだけでは答えを十分に隠せない。下の画面を取得し、選んだ文字色を背景に近づける方式へ進んだ | `f9e093e` |
| 灰色になる問題 | 全体を白黒に変換すると、拾った色と異なる赤が灰色で残った。色相が近い部分だけを変換し、濃淡の違う赤も対象にした | `b4d315a` |
| 移動の引っかかり | 移動のたびに操作受付と同じスレッドで変換していた。変換を非同期化し、更新要求を溜めないようにした | `7df23b4` |
| 広いキャッシュ | ユーザーが周囲まで取得する方法を提案。移動中は切り出しで表示し、端の接近や期限切れで補充するようにした | `884770a` |
| 赤い背景 | 問題の位置を示す役割を残すため、白い背景と隠す文字を同じ薄赤に変換。白い表示にも戻せるようにした | `884770a` |
| 撮影用の別版 | 自己参照を防ぐキャプチャ除外が録画にも効いていた。撮影用では画面を固定してから除外を解除し、循環する取り込みを防いだ | `8c8263c` |
| 初回公開 | MITライセンス、通常版・撮影用の検証、配布ZIPの生成を整備した | `99bdfd7` |
| ブランド素材 | 問題集風のPDFは紹介の目的を外した。広い背景をClaude Opusに渡し、赤い言葉の出現で意味が変わる撮影素材を制作した | `8001b24` |

## 続けたい進め方

- 実際に使った感想を仕様へ戻す。「文字が灰色」「移動がカクつく」から、変換方式や処理の分担を見直せた。
- ビルドだけで終えず、実際の画面取得・描画・キー入力を確認する。画面拡大率による座標ずれも、実画面の検証で見つかった。
- 学習用と撮影用の設定・実行ファイルを分け、紹介映像のための挙動を通常利用へ持ち込まない。
- 配布ZIPをスクリプトで生成し、公開先から取得したファイルのハッシュまで確認する。

## 失敗と次回の改善

| 失敗 | 次回の進め方 |
|---|---|
| 紹介の目的を掴む前に、一般的な問題集PDFを作った | 制作前に「誰に何を感じてもらうものか」「説明が必要か」を合わせる |
| 移動イベントに重い取得・変換を直接つないだ | 連続操作では、操作受付と処理の分離、要求の集約、キャッシュを最初に検討する |
| ビルド失敗後に古い実行ファイルの検証が走った場面があった | ビルド失敗で停止する。検証結果ファイルは実行前に除去し、終了コードと新しい結果を確認する |
| 外部キーの状態が自動検証へ影響した | 検証用のキー要求は、物理キーの修飾状態から独立させて実際の処理へ渡す |
| Opusへ最初から狭い構成を指定した | 利用場面、開発の経緯、ユーザーの言葉、却下された案を渡し、方向性から提案してもらう |
| 長い外部モデルへの依頼で出力待ちと失敗を区別しきれなかった | 標準入力と構造化出力を使い、終了コード・成功状態・実際の本文を確認する。取得していない案をモデルの提案と呼ばない |
| 生成した販促素材をソースと一緒に追跡した | 公開前にcloneした人に必要かを確認する。生成物の除外と、それを必須にしている処理の修正をセットで行う |

## ソースと生成物の境界

| 場所 | 用途 | Gitで追跡するか |
|---|---|---|
| `Akashi.cs`、ビルド・配布スクリプト | アプリを再現するソース | する |
| `docs/` | 判断理由と開発の記録 | する |
| `tools/` | 素材を再生成するコードと編集用データ | する |
| `tmp/` | 外部モデルとのやり取り、ローカル依存ライブラリ、確認画像 | しない |
| `dist/` | 配布する実行ファイルとZIP | しない。配布物はGitHub Releasesへ置く |
| `output/` | 生成したPDFや撮影メモ | しない。手元のファイルと過去のGit履歴は残す |

通常の配布ZIP作成は `output/` がなくても動く。サンプルPDFの同梱は、ローカルで生成したあとに `package.ps1 -IncludeDemo` を指定する場合だけ行う。

## 現在の制約と検証

- 通常版は画面キャプチャから除外される。これは自分自身を再取得しないための仕様。
- 撮影モードは切り替え時の画面を固定する。PDFのページ送りやスクロール後は、解除してから入り直す必要がある。
- 色相が近い画像やほかの文字も変換対象になる。文字の意味を認識して答えだけを隠しているわけではない。
- キャッシュは左右256px・上下384px。端まで64px以下、または移動中に500ms以上経過すると補充する。大きな移動では更新まで端を背景色で埋める。
- 検証済みなのは操作の受付、色変換、キャッシュの表示位置、録画への表示切替。改善率やフレームレートの定量比較は行っていない。
- PDF生成コードはWindowsのフォントとPythonライブラリを使う。アプリ自体のビルドにはPythonは不要。
- 名前は `akashi` に決定。名称の重複は未調査。

次の変更では、ビルド失敗時の停止、通常版と撮影用の `--self-test`、配布ZIPの中身、Gitへ追加するファイルの範囲を確認する。生成物を除外したあとも、cloneしたソースだけで標準の配布処理が実行できることを保つ。
